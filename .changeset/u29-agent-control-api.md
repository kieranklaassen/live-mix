Agent control API (U29). `AgentController` is a tool surface over the score, the engine and a consumer's session: every U28 operation is a schema-described tool (`strip_set`, `clip_replace_from`, …, 51 in all) beside the coach's intents — `steer_music` (calmer/stronger/more-intense/change/brighter/darker through the Camelot/intensity ladder), `set_intensity`, `set_music_volume`, `set_ambience`, `duck` (softer under voice), `more_space`, `extend_section`, `advance_section`, `set_breath_pace`, `fade_out`, `match_key` — plus `get_state` and `undo`. `call(name, args, { author, dryRun })` validates against the tool's JSON Schema, runs the safety rails, compiles to score operations and effects, applies through `ScoreDocument.apply` with the agent as author, and records an audit trail (`AgentAuditLog`) that cross-references the `OperationLog`. `listTools()`, `toOpenAiTools()` (Responses/Realtime flat or Chat shape) and `toAnthropicTools()` export the catalogue. Rails (`Rails`, `DEFAULT_RAILS`, all configurable) outrank the agent: fader range 0..1, short-term LUFS (−14) and true-peak (−1 dBTP) ceilings read from the master meter (clamp or reject), gain slew (1/s per parameter), no hard mute or near-silence of the voice role while speaking, no muting or removing the music, per-tool rate limits with retry hints, consent scopes (`arrange`, `structure`) for structural operations, extension and fade bounds; dry runs apply nothing and consume no budget. `snapshot()` is a ≤ 2 KB prompt document (transport, section, now playing and upcoming, levels, meters, engaged devices, recent calls) with `diffSince(cursor)` and a settable cadence. The intensity ladder and steering resolver move from Breathwork Live's `musicResolver.ts` into `src/core/music/intensity.ts` (`targetIntensity`, `resolveReplacementTracks`, `rankTonal`). A zero-dependency JSON Schema subset validator (`validateSchema`) ships with it; tests check every tool schema under Ajv 2020-12 strict mode. Docs in `docs/agent-api.md`.
