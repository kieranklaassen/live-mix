Agent-authored scores (U38). `SessionScript` is the tuin breathwork skill's three-part script as typed JSON — grounding, active and integration parts with target durations, a breathing pattern each, timed voice cues with `<2s>` pause tags, breath holds, theme and intensity — with `SESSION_SCRIPT_SCHEMA` as the prompt contract a planner fills (the library never calls a model), `validateSessionScript` for the semantics the schema cannot express, `checkScriptCanon` for the tuin / Breathwork Live canon (three parts in order, active always intensity 3, exactly two holds, the closing cue, one sound release two thirds through, cue cadence, "part" never "journey") and `parseSessionScript` tying them together; `sessionScriptPromptContract()` renders schema and rules for a system prompt. `compileScript(script, library, options)` compiles a script into a score deterministically: music selected by a behaviour-for-behaviour port of tuin's `music_selector.py` (`selectTracksForSession`, `selectTracksForScript`) with `pythonChooser(seed)` reproducing CPython's `random.choice` (`PythonRandom`: MT19937, `getrandbits`, `_randbelow`) — 90 parity goldens recorded from the tuin script by `scripts/selector-parity-goldens.py` — full tracks chained with equal-power crossfades (or `fit: 'script'` with pydub's boundary fades), voice clips at part start + 7 s + cue time with a 2 s minimum gap from a `VoiceProvider` (`estimatedVoiceProvider`, `staticVoiceProvider`, `synthesizeVoice` around any async TTS), a ducking lane on the music fader around every cue (−6 dB, 80 ms / 800 ms), an optional looped ambience bed and a breath-guide `inputGain` lane shaped by the breathing pattern (silent through holds, switching at cues that carry a `breathing` override). `compileScriptDetailed` adds the timeline, the selection and warnings; `operationsToLoad` gives the one-batch, undoable operations that put a compiled score into a live document. `renderScriptToWav` compiles, bounces the master through `renderScore` and encodes WAV; a golden asserts a compiled script schedules identically through `loadScore` (live) and `renderScore` (offline). `scriptTools()` / `ScriptAuthoring` add three tools to the `AgentController`: `author_script` (validate, compile, load; `structure` consent; canon breaks rejected with their rules), `preview_section` (a part's timeline; optional seek of a stopped transport) and `render_session` (an offline WAV render job). Consumer tools' declared `rateLimit`s are now enforced by the rails (the controller's `rails.rateLimits` table still wins). Docs in `docs/agent-authored-scores.md`, including the proposal for tuin posting a script instead of rendering itself and the parity status.
