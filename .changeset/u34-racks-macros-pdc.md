Racks, macros and plugin delay compensation (U34, R10/R12). `Rack` is a composite `Device` of parallel `Chain`s (ordered inserts, own gain/pan/mute, reserved key/selector zones) summed to one output with a linear `mix` and a dry/wet bypass; it goes anywhere a device does and nests. Eight macros (`macro1`…`macro8`) are U19 `Macro` controls mapped onto inner device params with a range and a curve in the param's taper (`mapMacro`, `Macro.ts` maths, `macroTarget` for the ModMatrix); registered as `rack` in the default registry so U23 presets cover macro and mix values, and `captureRackPreset` / `createRackFromPreset` / `serializeRackPreset` / `parseRackPreset` cover the whole structure with every device as a U23 preset. Delay compensation: the `Device` contract gains an optional `latencySamples` (NodeDevice and WasmDevice always report it; the true-peak limiter exactly via `truePeakLimiterLatencySamples`), chains inside a rack are aligned to the longest with sample-exact `DelayNode`s, `engine.latencyReport()` exposes own/total/arrival/deficit latency per track, group, bus and the master, and `engine.alignLatency()` inserts `AlignmentDelay` stages so clip and instrument tracks arrive together with the longest path — live inputs are never delayed unless asked. `Bus.destinationNode`, `MasterLimiter.latencySamples`, `rampParamTo` and `definitionLatencySamples` are exported. Nothing is added to the default graph.
